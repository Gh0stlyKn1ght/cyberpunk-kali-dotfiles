## What this final branch adds

### Kiroshi Kali intelligence

Kiroshi now enriches visible installed applications with:

- Kali-style security category
- executable path
- Debian/Kali package owner
- package version
- favorites
- recent launch ordering
- package/category-aware search

State files:

```text
~/.config/cyberkali/favorites
~/.config/cyberkali/recent-tools
```

New CLI:

```bash
cyberkali tool-search <term>
cyberkali favorite add <binary>
cyberkali favorite remove <binary>
cyberkali favorite list
```

### Notification actions and DND

AstalNotifd remains the notification bridge. The latest notification object is exposed through an action panel using the app-provided Freedesktop actions.

New controls:

```text
SUPER + SHIFT + A   latest notification actions
SUPER + SHIFT + D   toggle DND
```

New CLI:

```bash
cyberkali notification-actions
cyberkali dnd
```

Important boundary: notification action invocation only works while the original sending application can still receive the action event.

### Battery and power profiles

The System Control Matrix now includes:

- battery percentage/state through UPower
- current `powerprofilesctl` profile
- power-saver
- balanced
- performance

These degrade to N/A when the hardware/backend does not support them.

### Deeper side telemetry

The local host side panel now includes:

- OS
- uptime
- load
- battery
- power profile
- active-interface RX/TX rate
- current MPRIS media title

## Live validation still required

Do not call the project stable until this is tested inside the actual target Kali Hyprland session.

### 1. Installer dry run

```bash
./install.sh --dry-run
```

Verify no required package name is unavailable on current Kali Rolling.

### 2. Full install / upgrade path

```bash
./install.sh --flavor red
```

Then log out and back in so `/usr/local` GI/library paths from `~/.profile` are active.

### 3. Core health

```bash
cyberkali doctor
cyberkali status
cyberkali monitors
```

### 4. Kiroshi intelligence

Test:

```bash
cyberkali favorite add nmap
cyberkali restart
cyberkali launcher
```

Verify:

- favorite sorts above normal apps
- package/version resolves correctly
- binary path resolves correctly
- searching `RECON`, `WEB`, `WIRELESS`, etc. works
- launcher remains responsive while typing

Potential weak point: package resolution uses synchronous local `dpkg-query` calls for visible results and should be watched for UI latency.

### 5. Notification bridge

```bash
notify-send 'CyberKali' 'normal desktop notification test'
cyberkali messages
```

Then test DND:

```bash
cyberkali dnd
notify-send 'CyberKali DND' 'this should not produce a CyberKali popup'
```

### 6. Notification action traversal

This is one of the most important live checks.

The code traverses AstalNotifd's `GLib.List<Action>` using `length()` / `nth_data()`.

Test with an application that sends real notification actions. Verify:

```bash
cyberkali notification-actions
```

If GJS exposes the list differently on the pinned GI build, fix only the list adapter rather than changing the notification architecture.

### 7. Power profiles

```bash
powerprofilesctl get
cyberkali controls
```

Test each profile only if the host reports it as supported.

VMs/desktops may show N/A. That is acceptable.

### 8. Side telemetry

Verify traffic rate after:

- Ethernet/Wi-Fi change
- VPN connect/disconnect
- dock/USB adapter change

If counters appear stale:

```bash
cyberkali restart
```

### 9. Multi-monitor regression

Test:

- primary display
- secondary display
- mixed scale
- unplug/replug
- restart after hotplug

### 10. Amber regression

```bash
cyberkali flavor amber
```

Verify CRT overlay remains click-through and does not cause unacceptable GPU usage.

## Known design choices

- No GitHub Actions added.
- No Vercel/deployment workflow.
- No privileged CyberKali daemon.
- AGS is never run as root.
- Package installation is never automatic from Kiroshi.
- Existing notification daemons are never automatically disabled.
- Normal Kali desktop should remain installed for recovery.
- Optional hardware controls fail soft.
- CyberKali state is local and intentionally lightweight.

## Recovery rule

If the desktop becomes unusable:

```text
CTRL+ALT+F2
```

Then:

```bash
pkill -f 'ags run.*config/ags/app.ts' || true
systemctl --user stop cyberkali-package-watch.service || true
```

Return to the normal Kali desktop session and inspect the README recovery section before changing base OS packages.
